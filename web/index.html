HTTP 402 · EIP-3009

Your agent pays, not just asks.

x402 puts the price inside HTTP. A stall answers 402 with a price tag, the agent signs a transfer authorization, and the facilitator settles it on BNB Chain once the stall has delivered.

PAYMENT-REQUIREDPAYMENT-SIGNATUREPAYMENT-RESPONSEX402 V2

Ask

The agent calls a stall. The stall answers 402 with the amount, token, network and recipient.

← PAYMENT-REQUIRED

Sign

The agent signs an EIP-3009 TransferWithAuthorization and asks again. No approval and no gas.

→ PAYMENT-SIGNATURE

Serve

The facilitator verifies the signature, then the stall does its work. A failed stall settles nothing.

POST /verify

Settle

The facilitator sends the transfer on BNB Smart Chain and pays the gas. The agent gets the data and a receipt.

← PAYMENT-RESPONSE

Gasless where it matters.

Only the facilitator holds BNB. Buyers sign, stalls serve, and the chain only sees the settlement.

Buyers never hold gas

The agent wallet only needs pUSD. Its signature is the whole payment; the facilitator broadcasts it.

Failures cost nothing

Settlement runs after the stall answers. An offline model or a broken upstream is never charged.

Keys stay on your machine

The facilitator, the stalls and the agent run locally. The facilitator only settles your token to your seller.

Six stalls

Six stalls. One facilitator.

Each stall prices its own requests and settles through the same facilitator. Change prices in .env and add gateway routes in JSON.

Open the market in minutes.

        
Windows, macOS and Linux. Node.js 22 is the only requirement, and the local chain needs no faucet.

      

      

        

          
01Install

          
Pull the dependencies: the x402 SDK, viem, Hardhat and the MCP SDK.

          
npm install

        

        

          
02Build the contracts

          
Compiles Pasar USD and the TokenProbe simulator, then exports their ABIs.

          
npm run build

        

        

          
03Open the market

          
Starts a local chain, deploys pUSD, and opens the facilitator, the stalls and the gateway.

          
npm run dev
# → http://127.0.0.1:4021

        

        

          
04Watch the agent shop

          
The demo buys from every stall and prints what each payment cost.

          
npm run demo
# or shop yourself:
npm run agent -- 0x0E09FaBB73Bd3Ade0a17ECC321fD13a19e81cE82

        

        

          
05Move to BSC testnet

          
Only the facilitator needs test BNB. The agent signs and never pays gas.

          
npm run setup
# fund the facilitator: bnbchain.org/en/testnet-faucet
npm run deploy
npm run dev

        

        

          
06Shop from Claude

          
Register the MCP bridge and ask Claude to check a token for you.

          
claude mcp add pasar-x402 -- npx tsx /path/to/pasar-x402/src/agent/mcp-bridge.ts

        

      

    

  


  

    

      
Questions before you plug in.

      

        
Is it really free to run?
On the testnet, yes: a test token, test BNB from the faucet, public RPC endpoints and no paid APIs. On mainnet the facilitator pays a fraction of a cent in gas per settlement.

        
Why a test token instead of USDT?
USDT and USDC on BSC do not implement EIP-3009, so they cannot be paid with a signature alone. Pasar USD (pUSD) does. For mainnet, switch to x402's Permit2 flow (one approval, then signatures) or use a BSC facilitator.

        
Does the buyer pay gas?
No. The agent only signs. The facilitator sends the transaction and pays the gas.

        
What happens when a stall fails?
Payment settles only after the stall answers successfully. An offline model, a broken upstream or an unknown content id costs the buyer nothing.

        
Can Claude use it?
Yes. The MCP bridge exposes market_token_check, market_ask_ai, market_read_content and market_wallet to Claude Code, Claude Desktop or Cursor, all within the agent's budget.

        
Can I accept payments from anywhere?
Crypto payments are restricted in some countries; in Indonesia crypto is not a legal means of payment. Use Pasar x402 for learning, hackathons and testnets, and check the rules where you operate before taking real money.
